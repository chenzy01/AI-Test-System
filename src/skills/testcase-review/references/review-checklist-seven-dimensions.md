# 评审检查清单（七维度）

对每条用例按以下七维度逐项检查。命中任意检查项的问题点，登记为 RV 问题。

## 一、溯源性

- [ ] 用例回链 TP 编号，TP 回链 RA 编号，链路无断裂
- [ ] 无孤儿用例（无上游 TP/RA 的 TC）、无孤儿 TP（无 TC 的 TP）、无孤儿 RA（无 TP 的 RA）
- [ ] 需求溯源字段填写的 RA/TP 编号真实存在

## 二、覆盖率

- [ ] 每个 TP 至少 1 正向 + 1 异常/边界用例
- [ ] 有输入的功能点覆盖边界值（最小/最小-1/最小+1/最大/最大-1/最大+1）
- [ ] 测试类型覆盖无空洞（功能/边界/异常/性能/兼容/安全）
- [ ] 状态迁移覆盖合法边 + 非法边；决策表组合全覆盖或注明裁剪

## 三、可执行性

- [ ] 步骤动词开头、操作对象明确、无歧义
- [ ] 每步含具体数据值，执行者不查文档即可执行
- [ ] 预期结果可观测、可验证，精确到字段/状态/错误码
- [ ] 无禁词（「校验通过」「提示合理」「显示相关提示」「处理正确」等）

## 四、粒度

- [ ] 一个用例只验证一个验证点，无复合断言
- [ ] 步骤数合理（≤15 步），过长已拆分
- [ ] 无碎片化用例（同一验证点拆成多条）

## 五、冗余度

- [ ] 无完全重复的用例（同输入 + 同断言 + 同后置状态）
- [ ] 无语义重复（表述不同但验证点相同）
- [ ] 等价用例已合并

## 六、优先级合理性

- [ ] 优先级符合 P0/P1/P2 定义（P0=核心流程/阻断缺陷；P1=重要功能；P2=一般场景）
- [ ] 核心流程用例为 P0，无凭感觉定级

## 七、数据具体性

- [ ] 测试数据含名称 + 具体值 + 构造方式
- [ ] 无「任意值」「合法值」「有效数据」等空泛表述
- [ ] 前置条件自包含（账号 + 数据状态 + 环境状态），不依赖其他用例执行顺序
