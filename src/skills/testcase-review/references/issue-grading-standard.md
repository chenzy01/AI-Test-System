# 问题分级标准

评审问题（RV）按影响程度分为三级：必须改 / 建议改 / 可选。

## 一、三级定义

| 级别 | 定义 | 典型问题 |
|------|------|---------|
| 必须改 | 阻断执行或导致误测，不改无法投入使用 | 用例无法执行、断言模糊、步骤夹带预期、隐式依赖、覆盖空洞（孤儿 TP/RA）、八大字段缺失 |
| 建议改 | 影响用例质量或导致漏测风险，建议限期修订 | 数据不可构造、步骤冗余/缺步、优先级错定、边界取值错误、非法状态边缺失 |
| 可选 | 优化性建议，不影响正确性 | 命名不规范、格式不统一、可读性差 |

## 二、分级判断流程

1. 先看是否「阻断执行/导致误测」→ 是则「必须改」。
2. 否则看是否「影响质量/漏测风险」→ 「建议改」。
3. 否则看是否「仅影响可读性/规范性」→ 「可选」。

## 三、分级示例

| 问题描述 | 维度 | 级别 |
|---------|------|------|
| 预期结果写「校验通过」，无法断言具体结果 | 可执行性 | 必须改 |
| 用例依赖「执行 TC-005 后」才能执行 | 可执行性 | 必须改 |
| RA-007 无任何对应 TP，覆盖空洞 | 覆盖率 | 必须改 |
| 测试数据写「任意手机号」 | 数据具体性 | 建议改 |
| 用例标题「测试登录」不规范 | 粒度/规范性 | 可选 |

## 四、修改建议要求

- 必须改 / 建议改：每条给「改前 → 改后」对照，改后达到可执行标准。
- 覆盖空洞类：给补点建议，引用测试设计方法（如「该字段需补 ±步长 边界用例」）。
- 可选：给统一修订规则即可，不逐条展开。
