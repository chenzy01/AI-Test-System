# 测试设计方法应用详解

把上游 TP 的「建议测试方法」落地为具体用例步骤与预期的方法对照。用例编写时按本表把每种方法展开为可执行步骤。

## 一、方法 → 用例落地对照

| 设计方法 | 用例步骤设计要点 | 预期结果设计要点 |
|---------|----------------|----------------|
| 等价类划分 | 每个有效/无效等价类取一个代表值作为测试数据 | 有效类→功能通过；无效类→拒绝+具体错误码/提示 |
| 边界值分析 | 步骤逐一遍历 边界±1 取值（最小/最小-1/最小+1/最大/最大-1/最大+1） | 边界内→通过；边界外→拒绝，断言具体文案或状态不变 |
| 决策表 | 每条规则列对应一个用例，步骤按条件组合依次设置 | 断言动作桩对应的输出（通过/拒绝/具体结果） |
| 状态迁移 | 步骤沿迁移边依次触发状态变更；非法边步骤尝试非法迁移 | 合法边→状态字段变为目标值；非法边→拒绝+状态不变+错误码 |
| 场景法 | 步骤写完整路径序列（基本流/备选流/异常流） | 断言路径终点状态与中间关键节点 |
| 错误推测 | 步骤构造高风险场景（并发、重复提交、超时） | 断言幂等/一致/回滚等防护结果 |

## 二、边界值用例步骤示例

TP：「验证数量字段（范围 1~10）的边界」。

| 用例 | 测试数据 | 步骤要点 | 预期 |
|------|---------|---------|------|
| 最小-1 | 数量 0 | 输入 0 提交 | 提示「数量必须 ≥ 1」，不提交 |
| 最小 | 数量 1 | 输入 1 提交 | 提交成功 |
| 最小+1 | 数量 2 | 输入 2 提交 | 提交成功 |
| 最大-1 | 数量 9 | 输入 9 提交 | 提交成功 |
| 最大 | 数量 10 | 输入 10 提交 | 提交成功 |
| 最大+1 | 数量 11 | 输入 11 提交 | 提示「数量必须 ≤ 10」，不提交 |

## 三、非法状态边用例示例

订单已「已取消」状态，非法边 = 取消 → 支付。

| 字段 | 值 |
|------|-----|
| 步骤 | 1. 进入订单列表<br>2. 定位已取消订单<br>3. 尝试点击「支付」 |
| 预期 | 1. 列表加载成功<br>2. 订单状态为「已取消」<br>3. 支付入口不可用，状态保持「已取消」 |
