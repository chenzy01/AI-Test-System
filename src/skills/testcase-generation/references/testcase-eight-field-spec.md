# 用例八大字段规范

用例（TC）的八大字段逐字段填写规范。每条用例必须八字段齐全，缺一即不合格。

## 一、字段填写规范

| # | 字段 | 必填 | 填写要求 | 反例（不合格） |
|---|------|------|---------|---------------|
| 1 | 编号 | 是 | TC-<模块简称>-<三位序号>，全局唯一连续 | 无模块前缀、跳号 |
| 2 | 名称 | 是 | 「验证XX时YY」格式：验证<动作>时<触发条件>，系统<期望> | 「下单用例」「测试登录」 |
| 3 | 需求溯源 | 是 | 关联 RA-ID 与 TP-ID；用例类型继承自 TP 的测试类型 | 无 RA/TP 回链 |
| 4 | 优先级 | 是 | P0/P1/P2，定义见 SKILL.md 输出约定 | 凭感觉定级 |
| 5 | 前置条件 | 是 | 账号 + 数据状态 + 环境状态，可独立构造 | 「系统正常」这类空前置 |
| 6 | 测试数据 | 是 | 名称 + 具体值 + 构造方式 | 「任意值」「合法值」 |
| 7 | 测试步骤 | 是 | 编号列表，每步 = 动词 + 对象 + 具体数据值 | 「输入数据」「进行校验」 |
| 8 | 预期结果 | 是 | 编号列表，与步骤一一对应，精确到字段/状态/错误码 | 「校验通过」「提示合理」 |

## 二、名称命名规范

格式：`验证<动作>时<触发条件>，系统<期望结果>`

| 示例 | 说明 |
|------|------|
| 验证提交订单时优惠金额超过订单金额 50%，系统拒绝并提示错误 | 动作+触发+期望齐全 |
| 验证输入数量为 0 时，系统提示「数量必须大于 0」 | 边界+精确文案 |

## 三、步骤与预期编写要点

1. 每步只写一个动作：动词 + 对象 + 具体数据值（如「在数量输入框输入 11」）。
2. 步骤只写执行动作，系统自动行为写入对应预期（如「系统扣减余额」写在预期）。
3. 预期与步骤编号一一对应，同编号对同一动作/断言。
4. 断言分四类：UI 断言（元素+文案/状态）、接口断言（方法+URL+响应码+字段）、数据断言（表+字段+值）、通知断言（渠道+接收方+消息字段）。
5. 等待/轮询写具体时长或条件（如「等待 5 秒后刷新页面」）。

## 四、测试数据构造方式枚举

| 构造方式 | 说明 |
|---------|------|
| 页面造数 | 通过 UI 操作构造 |
| 接口调用 | 通过 API 传入参数构造 |
| 预置 SQL | 直接写库构造 |
| 预置文件 | 上传构造文件 |
| 环境配置 | 改配置/开关构造 |
