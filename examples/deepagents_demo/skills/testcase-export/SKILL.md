# 用例输出技能（testcase-export）

## 一、技能定位

将用例集无损转换为交付格式。核心原则：

- **单一数据源**：所有格式先映射到统一的 10 字段标准契约，再从契约生成各格式，保证多格式导出内容一致；
- **无损转换**：导出后通过往返校验，字段、编号、步骤-预期配对不丢失不变化；
- **企业可用**：Excel 含下拉枚举与追溯矩阵、CSV 可被 Excel/平台直接导入、XMind 可直接评审展示。

支持格式与默认文件命名：

| 格式 | 适用场景 | 文件命名 |
|------|---------|---------|
| Markdown | 评审会材料、需求平台回填、Git 文档 | `<模块>-testcases.md` |
| CSV | 平台批量导入、数据交换 | `<模块>-testcases.csv` |
| Excel | 正式交付、测试管理平台上传 | `<模块>-testcases.xlsx` |
| XMind | 评审走查、脑暴展示 | `<模块>-testcases.xmind` |

## 二、标准字段契约（10 字段，所有格式的单一数据源）

| # | 字段 | 必填 | 格式约束 |
|---|------|------|---------|
| 1 | 用例ID | 是 | TC-xxx，连续编号 |
| 2 | 关联测试点 | 是 | TP-xxx；多值用分号分隔 |
| 3 | 模块 | 是 | 业务域名词短语 |
| 4 | 用例标题 | 是 | 「验证XX时YY」格式 |
| 5 | 优先级 | 是 | 枚举 P0/P1/P2 |
| 6 | 用例类型 | 是 | 枚举 功能/边界/异常/状态流转/权限/并发/性能/兼容性/安全 |
| 7 | 前置条件 | 是 | 多条用分号分隔，每条为可构造状态 |
| 8 | 测试数据 | 是 | 名称+具体值+构造方式 |
| 9 | 测试步骤 | 是 | 编号列表，每步 动词+对象+具体数据值 |
| 10 | 预期结果 | 是 | 编号列表，与步骤编号一一对应，精确断言 |

各格式的具体映射与转义规则见 `references/format-contracts.md`。

## 三、工作流程

按以下 6 个阶段顺序执行。

### 阶段 1：输入识别与目标格式确认

- 输入类型识别：
  - **路径 A（标准）**：用例编写报告 / 评审修订版用例表（含 TP 关联）；
  - **路径 B（裸用例）**：纯用例列表（无 TP 关联） → 关联测试点列填「—」，报告中标注追溯链缺失；
  - **路径 C（带评审材料）**：用例 + 评审报告 → Excel 导出时增加「评审问题」sheet，其余格式在文件末尾附评审问题清单。
- 目标格式：用户指定格式（可多选）；未指定时默认 Markdown。
- 输出范围：默认全部用例；用户指定模块/优先级筛选时按筛选导出并在说明中标注筛选条件。

### 阶段 2：字段标准化

- 将输入用例映射到 10 字段契约：
  - 字段缺省处理：可选字段缺省填「—」；**必填四要素（用例ID/用例标题/测试步骤/预期结果）缺失 → 拒绝导出**，提示回到 testcase-generation 补齐；
  - 枚举标准化：优先级/用例类型不在枚举内 → 按 `references/format-contracts.md` 第 1 节映射规则归一（无法映射时标注「未定义」并在导出说明中警告）；
  - 步骤/预期解析：将「1. xxx <br> 2. xxx」解析为编号列表结构，校验步骤编号数 = 预期编号数，不一致 → 拒绝导出并列出不一致的用例ID。

### 阶段 3：数据清洗

- 按目标格式的转义规则处理特殊字符（见 `references/format-contracts.md`）：
  - Markdown：`|` → `\|`，换行 → `<br>`；
  - CSV：逗号/双引号/换行按 RFC 4180 引号包裹与翻倍规则处理；
  - Excel：换行保留为单元格内换行（wrap text）；
  - XMind：文本节点自动转义 XML/JSON 特殊字符。
- 统一修剪首尾空白；保留用例内容原义，禁止改写步骤与预期措辞。

### 阶段 4：生成导出文件

- 按 `references/format-contracts.md` 各格式契约生成：
  - **Markdown**：模块分节 + 用例表格 + 可选详情视图；
  - **CSV**：UTF-8 BOM + 表头 + 每行一条用例（步骤/预期用 `\n` 字面量保持单行）；
  - **Excel**：用例总表（下拉枚举/冻结首行/自动换行） + 追溯矩阵 sheet + 评审问题 sheet（路径 C 时）；
  - **XMind**：中心主题 → 模块 → 用例 → 四分组（前置条件/测试数据/测试步骤/预期结果）→ 叶子节点，优先级 marker 约定；
- 同时导出多格式时，全部从同一份标准化中间数据生成。

### 阶段 5：导出校验（往返校验，全部通过才交付）

- 记录数校验：导出文件用例记录数 = 输入用例数；
- 字段完整性：每条记录 10 字段无缺失必填项；
- 配对校验：每条记录解析后步骤编号数 = 预期编号数；
- 转义往返校验：抽取含特殊字符（`|`、逗号、引号、换行）的用例抽样回读，与原始内容比对一致；
- 编码校验：CSV 为 UTF-8 with BOM；Excel/XMind 可正常打开解析。

### 阶段 6：输出交付说明

交付内容：文件路径清单 + 导出统计（用例数/模块数/优先级分布）+ 筛选条件说明（如有）+ 使用注意（如「CSV 供平台导入」「XMind 需 8.0+ 打开」）。

### 4.1 交付清单

| 文件路径 | 格式 | 用例数 | 说明 |
|---------|------|--------|------|

### 4.2 导出统计

| 统计项 | 值 |
|--------|-----|
| 用例总数 | — |

```

## 2. 标准化结果（字段映射/枚举归一/清洗记录）
## 3. 交付清单
## 4. 导出统计与校验结果
## 5. 使用注意与遗留问题
```

## 五、质量门禁（交付前逐项自检）

1. **无损性**：往返校验全部通过，字段与内容无丢失、无改写。
2. **一致性**：多格式导出内容来自同一中间数据，用例内容一致。
3. **必填完整性**：四要素缺失的用例已拒绝并退回，交付文件中无空必填项。
4. **配对完整性**：交付文件中所有用例步骤与预期编号一一对应。
5. **格式合规**：符合 `references/format-contracts.md` 对应格式契约（编码、转义、sheet/树结构）。

## 六、约束与禁止事项

- 只做格式转换与交付，禁止在导出环节修改用例内容（含措辞）；内容问题应回到 testcase-generation / testcase-review 处理。
- 必填要素缺失时拒绝导出并明确退回路径，禁止用占位符（如"待补充"）填充必填字段。
- 用户提供企业模板时，优先套用用户模板；模板字段与 10 字段契约不一致时，输出字段映射表说明对应关系。
