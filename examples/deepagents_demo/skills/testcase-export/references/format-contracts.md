# 导出格式契约库（references/format-contracts）

> 渐进式披露文件：SKILL.md 阶段 2/3/4 引用本文件。定义各格式的字段映射、转义规则与结构 schema。

## 1. 枚举标准化映射

| 原始值（输入中可能出现的写法） | 标准值 |
|------------------------------|--------|
| 高 / P0 / 最高 / 紧急 | P0 |
| 中 / P1 / 高 | P1 |
| 低 / P2 / 中 / 一般 | P2 |
| 功能测试 / 正常 / happy path | 功能 |
| 边界测试 / 边界值 | 边界 |
| 异常测试 / 异常场景 | 异常 |
| 状态流转 / 流程 | 状态流转 |
| 权限 / 越权 | 权限 |
| 并发 / 压力（仅指并发正确性） | 并发 |
| 性能 / 响应时间 | 性能 |
| 兼容 / 浏览器 | 兼容性 |
| 安全 / 注入 | 安全 |

无法映射的值保留原文并标注「未定义」，在导出说明中警告。

## 2. Markdown 契约

- 结构：`# <项目>-<模块>用例集` → `## <模块名>` → 每个模块一张表格 + 可选「详情视图」小节。
- 列顺序（固定）：用例ID | 关联测试点 | 用例标题 | 优先级 | 用例类型 | 前置条件 | 测试数据 | 测试步骤 | 预期结果。
- 步骤/预期：单元格内编号列表，多条用 `<br>` 分隔（与上游用例表格式一致，不重新编号）。
- 转义：`|` → `\|`；单元格内换行 → `<br>`；表格分隔行 `|---|` 列数必须与表头一致。
- 详情视图（可选，长步骤用例推荐）：每条用例一个小节，`### [P0] TC-012 验证余额充足时余额支付成功`，步骤与预期并列代码块或列表，便于评审逐条核对。
- 文件末尾（路径 C 输入时）：附「评审问题清单」表格（问题ID/用例ID/级别/问题描述）。

## 3. CSV 契约

- 编码：UTF-8 with BOM（Excel 直接打开不乱码）。
- 分隔符：逗号；行结束符：CRLF。
- 转义（RFC 4180）：字段含 逗号/双引号/换行 时整体用双引号包裹，内部双引号翻倍（`"` → `""`）。
- 多行字段（步骤/预期）：默认用字面量 `\n` 分隔编号条目，保证一条用例一行；用户指定 multiline 时改用真实换行（RFC 4180 引号包裹）。
- 表头：10 字段契约原样输出，列顺序同 Markdown。
- 每行 = 一条用例；记录顺序与输入一致（保持 TC 编号升序）。

## 4. Excel 契约

**Sheet1「用例总表」**：
- 列：10 字段契约，顺序同 Markdown。
- 单元格换行：步骤/预期内编号条目用单元格内换行（wrap text 开启）。
- 数据校验（下拉枚举）：优先级列限 P0/P1/P2；用例类型列限 9 枚举。
- 样式：表头行加粗 + 底色填充 + 冻结首行；建议列宽：用例ID 10 / 标题 40 / 前置条件 30 / 测试数据 30 / 步骤 60 / 预期 60。
- 生成方式：openpyxl 或 xlsxwriter（优先 openpyxl，支持 data validation）。

**Sheet2「追溯矩阵」**：
- 列：测试点ID | 用例ID | 需求点ID（需求点从上游 REQ 映射，缺省填「—」）。
- 按测试点ID 升序排列。

**Sheet3「评审问题」（仅路径 C 输入时）**：
- 列：问题ID | 用例ID | 维度 | 级别 | 问题描述 | 优化方案。

## 5. XMind 契约（结构树模式）

树 schema（自上而下 5 层）：

```
第1层 中心主题：<项目名>-<模块>用例集（v<版本> <导出日期>）
第2层 模块节点：<模块名>（如 支付）
第3层 用例节点：<用例ID> <用例标题>（如 TC-012 验证余额充足时余额支付成功）
第4层 分组节点（固定 4 个）：前置条件 / 测试数据 / 测试步骤 / 预期结果
第5层 叶子节点：
  - 前置条件组 → 每条条件一个叶子
  - 测试数据组 → 每条数据一个叶子
  - 测试步骤组 → 步骤1..n 各一个叶子
  - 预期结果组 → 预期1..n 各一个叶子（编号与步骤一一对应）
```

- 优先级 marker 约定：用例节点加文本前缀 `[P0]`/`[P1]`/`[P2]`，同时设置 XMind 优先级 marker（P0→priority-1 红旗、P1→priority-2、P2→priority-3）。
- 生成方式：优先 `pip install xmind`（xmind SDK）生成 .xmind；环境无 SDK 时输出 FreeMind 兼容 .mm（XML，XMind 可直接导入），并在交付说明标注。
- 特殊字符：文本写入前按目标格式（JSON/XML）转义 `<>&"`。

## 6. 往返校验脚本要点

- CSV 回读：`csv` 模块按 RFC 4180 解析，比对记录数与字段值；
- 抽样用例：选取含 `|`、`,`、`"`、换行、emoji 的用例各 1 条做转义往返比对；
- 配对校验：解析步骤/预期编号列表，比对两侧编号集合完全一致；
- 编码校验：CSV 文件头 3 字节 = EF BB BF（BOM）。
