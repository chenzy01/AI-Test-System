# 用例评审技能（testcase-review）

## 一、技能定位

对测试用例集进行**多维度量化评审**，产出三类结果：

1. **问题清单**：按 A/B/C 三级列出缺陷，每条给出「改前 → 改后」对照；
2. **量化评分**：五维评分（覆盖度/可执行性/逻辑性/异常流覆盖/规范性）与总评等级；
3. **评审结论**：通过 / 有条件通过 / 退回，以及修订建议。

评审对象为用例集（TC）；上游材料（需求分析报告、测试点报告）用于覆盖度维度评审。

## 二、评审维度（总览）

| 维度 | 权重 | 核心问题 |
|------|------|---------|
| 覆盖度 | 30% | 需求→测试点→用例追溯是否完整？类型与边界是否全覆盖？ |
| 可执行性 | 30% | 步骤能否直接执行？数据能否构造？断言是否精确？ |
| 逻辑性 | 20% | 步骤顺序与预期是否一一对应？前置条件是否充分？用例是否独立？ |
| 异常流覆盖 | 15% | 四类无效输入与八类异常是否覆盖？非法状态边是否覆盖？ |
| 规范性 | 5% | 编号、命名、优先级、模块、格式是否合规？ |

详细检查清单见 `references/review-criteria.md`。

## 三、工作流程

按以下 6 个阶段顺序执行。

### 阶段 1：输入识别与评审范围声明

- 收集输入：用例集（必选） + 上游材料（需求分析报告 / 测试点报告 / 原始需求文档，可选）。
- 声明评审范围：评审的用例数量、模块、上游材料清单。
- **无上游材料时**：覆盖度与异常流覆盖两维度降级为「基于用例自身可推断部分」（如边界值合理性），在报告中显著标注「覆盖度评审受限：缺上游需求/测试点材料」，该维度不参与评分或按最低档计分并说明。

### 阶段 2：逐用例静态检查

对每条用例按 `references/review-criteria.md` 第 1 节五维检查清单逐项打勾：

- 每条用例完整走查一遍步骤，模拟执行者视角判断可执行性；
- 逐条预期核对是否命中全局禁词清单（"校验通过""提示合理""显示相关提示""处理正确"等）；
- 检查步骤-预期编号一一对应、步骤夹带预期、隐式用例依赖（"执行 TC-xxx 后"）；
- 检查优先级、模块、标题、编号合规性。
- 发现的问题登记为 RV-xxx（评审问题），记录：用例ID、维度、问题描述、级别。

### 阶段 3：覆盖度分析

- 构建 REQ→TP→TC 追溯链：找孤儿 REQ（无 TP）、孤儿 TP（无 TC）、孤儿 TC（无上游）；
- 对照测试类型枚举（功能/边界/异常/状态流转/权限/并发/性能/兼容性/安全）检查每个 REQ 的类型覆盖空洞；
- 对照 `test-point-extraction` 技能的边界规则（±步长）与 8 类异常清单、四类无效输入（不传/类型错/超界/格式错）检查遗漏；
- 检查判定表组合与状态迁移边（含非法边）在 TC 层的落地情况；
- 输出覆盖矩阵，空洞处标注「缺失」并登记为 RV 问题。

### 阶段 4：问题分级与评分

- 按 `references/review-criteria.md` 第 2 节将每个 RV 定为 A/B/C 级：
  - **A 级（阻断）**：用例无法执行、断言模糊、步骤夹带预期、隐式依赖、覆盖空洞（孤儿 TP/REQ）；
  - **B 级（重要）**：数据不可构造、步骤冗余/缺步、优先级错定、边界取值错误、非法状态边缺失；
  - **C 级（建议）**：命名不规范、格式不统一、可读性差。
- 按 `references/review-criteria.md` 第 3 节评分模型计算五维得分与总分（A 级扣 20 分/条、B 级扣 10 分/条、C 级扣 3 分/条，维度得分下限 0；总分=各维度得分×权重之和）。
- 按第 4 节结论规则给出评审结论。

### 阶段 5：优化方案生成

- 每个 A/B 级问题必须给出「改前 → 改后」对照（改后内容达到可执行标准，禁止只写"请修改"）；
- 覆盖空洞类问题给出补点建议（引用 test-point-extraction 的推导方法，如"该字段需补 ±步长 边界用例"）；
- C 级问题给出统一修订规则（如"全部标题统一为『验证XX时YY』格式"）即可，不逐条展开。

### 阶段 6：输出评审报告

按第 4 节输出契约生成报告，对照 `templates/review-output-template.md` 检查字段完整性。

## 四、输出契约

### 4.1 评审结论与评分（报告首部）

```
评审结论：退回 / 有条件通过 / 通过
总分：XX（等级：优秀/良好/合格/不合格）
| 维度 | 权重 | 得分 | 加权分 | 主要问题数（A/B/C） |
```

### 4.2 问题清单（核心产物）

| 问题ID | 用例ID/范围 | 维度 | 级别 | 问题描述 | 优化方案（改前 → 改后） |
|--------|-----------|------|------|---------|------------------------|

- A/B 级必须给出改前→改后对照；覆盖空洞类问题「用例ID」填「—」，「范围」写 REQ/TP 编号。

### 4.3 覆盖矩阵

| REQ | 功能 | 边界 | 异常 | 状态流转 | 权限 | 并发 | 结论 |
|-----|------|------|------|---------|------|------|------|

空洞单元格标注「缺失」，并在问题清单中对应 RV 条目。

### 4.4 报告结构

```
# 测试用例评审报告
## 1. 评审范围与输入材料
## 2. 评审结论与评分
## 3. 问题清单（RV）
## 4. 覆盖矩阵
## 5. 优化方案汇总（A/B 级改前→改后、C 级修订规则）
## 6. 修订建议与复审要求
```

## 五、评审结论规则

| 条件 | 结论 |
|------|------|
| 存在 A 级问题 | 退回（修订后必须复审） |
| 无 A 级，总分 ≥80 | 有条件通过（B 级问题限期修订） |
| 无 A/B 级，总分 ≥80 | 通过 |
| 总分 <70 | 退回（不论问题级别） |

## 六、约束与禁止事项

- 只评审与给方案，不擅自批量改写全部用例；用户要求直接修订时，输出「修订版用例表」并保留原编号与修订说明。
- 评审标准以本技能及全局约定（编号契约、禁词清单）为准；用户有自定义评审标准时，优先用户标准并在报告中声明采用的标准来源。
- 覆盖度结论必须基于追溯链证据（孤儿 REQ/TP 列表），禁止凭印象下"覆盖不全"结论。
- 修改建议禁止引入上游未确认的新需求；涉及需求空白时建议回到 requirements-analysis 登记 CL。
