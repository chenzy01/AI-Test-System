# 需求提取规则库（references/extraction-rules）

> 渐进式披露文件：SKILL.md 主流程引用本文件，仅在执行挖掘/识别/方法选择时加载。

## 1. 九大隐性需求挖掘维度

对每个 REQ 逐一过筛以下 9 个维度。触发信号命中 → 挖掘对应规则；规则内容无法确定 → 登记 CL。

### 1.1 数据约束
- 触发信号：需求提到字段但未给全定义。
- 必须挖掘：类型、长度（min/max）、取值范围、精度（小数位数）、必填/选填、默认值、唯一性、格式（正则）、枚举全集、空值语义（null / 空串 / 0 是否等价）。
- CL 示例：「手机号字段是否允许 11 位以外的长度？国家码 +86 是否计入长度校验？」

### 1.2 状态流转
- 触发信号：需求出现状态类词汇（待支付/处理中/已完成/冻结…）或审批、取消、退回、撤回。
- 必须挖掘：完整状态机（初始态、终态、合法迁移、非法迁移）、状态变更触发条件、状态停留时效（超时自动流转？）、历史状态留存。
- 工具：绘制状态迁移表，逐边（含非法边）设计 TP。

### 1.3 权限隔离
- 触发信号：多角色系统，出现"管理员""仅 XX 可操作"。
- 必须挖掘：每个操作的允许角色、数据可见范围（本部门/下级/本人）、越权行为定义（提示文案 or 静默 or 错误码）。

### 1.4 并发一致性
- 触发信号：扣减、库存、名额、计数、秒杀、同时操作同一对象。
- 必须挖掘：并发写同一资源的行为（悲观锁/乐观锁/幂等）、重复提交去重键、超卖/超扣边界。

### 1.5 异常恢复
- 触发信号：调用外部系统、支付、消息、文件上传、批量任务。
- 必须挖掘：依赖超时/失败时的表现、重试策略与次数、补偿机制（回滚/冲正）、部分成功场景（批量操作第 N 条失败时前 N-1 条的去向）。

### 1.6 性能容量
- 触发信号：列表、报表、批量导入导出、大文件上传。
- 必须挖掘：数据量上限（列表最大条数/导入最大行数）、响应时间指标、并发用户数。

### 1.7 兼容适配
- 触发信号：多端（Web/App/H5/小程序）、多浏览器、多分辨率。
- 必须挖掘：覆盖端清单、最低支持版本、降级策略（低版本禁用 or 提示升级）。

### 1.8 安全合规
- 触发信号：登录、密码、敏感数据、支付、数据导出。
- 必须挖掘：密码强度规则、敏感字段脱敏展示、加密传输、日志中的敏感信息处置、审计日志留存周期。

### 1.9 可审计性
- 触发信号：关键操作（审批、资金、权限变更、删除）。
- 必须挖掘：操作日志字段（操作人/时间/IP/前后值）、日志查询入口、日志不可篡改性。

## 2. 边界识别规则

对每个含 数值/长度/时间/数量/集合/枚举 的字段应用以下七类边界。以「金额上限 1000 元、步长 0.01」为例：

| 边界类型 | 取值规则 | 示例值 |
|---------|---------|--------|
| 最小值 | 字段允许的最小值 | 0.01 |
| 最大值 | 字段允许的最大值 | 1000.00 |
| 临界值 | 边界值 ± 最小步长 | 999.99 / 1000.01 |
| 空值 | 不传 / null / 空串 | 不传金额字段 |
| 非法类型 | 类型不符 | 传字符串 "abc" |
| 超界值 | 远超上下限 | -100 / 100000 |
| 精度边界 | 小数位数边界 | 0.001（3 位小数） |

注意：临界值必须取「边界 ± 最小步长」，禁止笼统写"边界附近"；无明确步长时按 1 处理并写入备注。

## 3. 八类异常流程识别清单

逐 REQ 过筛以下 8 类异常，命中即生成异常 TP 或 CL：

1. **输入非法**：必填缺失、格式错误、超长、特殊字符、SQL 注入/XSS 载荷、Unicode 边界（emoji/生僻字/零宽字符）。
2. **依赖失败**：DB/Redis/MQ/第三方接口超时、宕机、返回错误码。
3. **重复提交**：双击、重发请求、幂等键重复。
4. **并发冲突**：同资源同时读写、版本冲突。
5. **权限不足**：未登录、无权限、越权访问他人数据。
6. **资源耗尽**：磁盘满、连接池耗尽、内存溢出。
7. **超时中断**：会话过期、请求中断、事务超时。
8. **数据异常**：脏数据、历史数据迁移不兼容、编码错误。

## 4. 设计方法选择规则

| 需求特征 | 首选方法 |
|---------|---------|
| 输入可划分为有限等价类 | 等价类划分（有效/无效等价类都必须覆盖） |
| 存在数值/长度/时间范围 | 边界值分析 |
| 多条件组合决定输出 | 判定表（覆盖全部条件组合，或正交裁剪并在备注注明裁剪依据） |
| 存在状态机 | 状态迁移（逐边覆盖，含非法迁移） |
| 业务为流程/路径型 | 场景法（基本流 + 备选流 + 异常流） |
| 经验性高风险点 | 错误推测（补充历史缺陷模式） |

## 5. 禁词清单（质量门禁强制检查）

测试点「期望输出」中出现以下表述即判定不合格，必须改写为具体字段+具体值/状态：

- "校验通过" / "校验失败" → 必须写明校验的字段与规则
- "提示合理" / "提示正确" → 必须写明提示文案或提示码
- "显示相关提示" / "相应信息" → 必须写明具体内容
- "处理正确" / "功能正常" → 必须写明具体状态与数据变化
- "可能" / "大概" / "大约" 等不确定副词 → 必须写明确值
